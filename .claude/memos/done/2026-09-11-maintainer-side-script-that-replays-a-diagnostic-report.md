# Maintainer-side script that replays a diagnostic report

Maintainer-side 'replay a report' script: takes a diagnostic report JSON (what 'Report a problem...' produces) and prints what the app would have shown for every achievement - displayName, description, which source won each field, under which language. IT MUST CALL THE APP'S OWN CODE, NOT A COPY. A reimplementation answers 'what does my copy do', never 'what did the user see', which is the only question a bug report asks - and it would drift from the resolver silently, so a replay could exonerate a build that is actually broken. No production change is needed for that: the three entry points are already public - AchievementMetadata.ParseUnlockStates, AchievementMetadata.ParseDefinitions, and AchievementMetadata.ResolvePreferringSchema(state, definitions, metadataDir, achievementName, language). That is also why the whole thing is derivable at all: text resolution is a pure function of four things the report already carries - the unlock state, the schema definitions, the achievement name, and config.content.language. SHAPE: a small console project in the repo referencing src. Not a test, and nothing added to the shipped app. WHY NOT IN THE APP: a 'resolution' section inside the report was proposed and rejected on 2026-09-03 - it is derivable from the other sections plus the version number, so shipping it would put redundant data on every user's disk and grow the file every reporter has to read. WHAT IT CANNOT DO: icon resolution. ResolveIconPath needs the real icon files, and metadataDir is the one input the report does not carry, so icons stay out of scope. THE SECOND TIME IS HERE: this harness was stood up ad hoc twice on 2026-09-03 and thrown away both times, and on 2026-09-06 ant-sh attached a real report to issue #7 - https://github.com/user-attachments/files/31882540/achievement-overlay-Assassins.Creed.Odyssey-812140.json, 93 achievements with a russian-carrying schema. Build it alongside the resolver fix for #7 and use it to MEASURE that fix's before/after on his actual file, rather than reasoning about what it would show.
