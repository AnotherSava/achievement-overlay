# Decide the two resolver fixes for issue #7

Decide the two resolver fixes for issue #7 - they were both recommended this session and neither was accepted or rejected. (1) LET PADDING MATCHES LEAD LIKE EXACT ONES: matchedExactly has exactly one production use, the '(leading, filling) = matchedExactly ? ...' ternary at the end of ResolvePreferringSchema, and dropping the distinction is the whole change. ANCHORS ARE SYMBOL NAMES ON PURPOSE: this memo first carried five src/AchievementMetadata.cs line numbers and all five were stale within a day, off by ~50 lines, from edits made in the very session that wrote them. The argument for it: we already tell users to strip the zeros by hand, which converts a collision-CHECKED padding match (FindDefinition accumulates candidates and refuses an ambiguous one) into an UNCHECKED exact one (the exact pass returns on its first hit); the icon already crosses the line text is forbidden to cross (the IconPath assignment tests 'definition != null', not matchedExactly); and exact digits-only matching has no collision guard at all, though real Steam games ship achievements named 1..29. (2) PER-FIELD LANGUAGE PREFERENCE, which is a separate shipped defect found while tracing #7 and nobody has reported: on an EXACT match the schema leads unconditionally, and GetDisplayText returns a plain string verbatim, ignoring the language argument - so a user whose emulator inlines {english, russian} in the unlock file, against an english-only schema, with Achievement text set to russian, gets english. Proposed single rule covering both: per field, prefer whichever source actually carries the selected language; if neither does, prefer the schema. That fixes #7, fixes the inline-object case, and lets matchedExactly be deleted rather than replaced with something subtler. NO LONGER BLOCKED - ANSWERED 2026-09-06: ant-sh confirmed his 812140 Goldberg config carries russian for EVERY achievement (built with gen_emu_sharp, https://github.com/otavepto/gen.emu.sharp, whose backup folder keeps the source app_model-812140.json). So fix (2) alone gives him russian and fix (1) is optional; the wizard-multi-language memo above is NOT his path. He attached a real 'Report a problem...' file to the issue - https://github.com/user-attachments/files/31882540/achievement-overlay-Assassins.Creed.Odyssey-812140.json - which is the before/after measurement input, so run the resolver against it rather than predicting the outcome (see the replay-script memo below). HIS OWN PROPOSED UI is a single checkbox, 'Prefer language texts from Goldberg config if they are available'. Weigh it rather than adopting it: the per-field rule needs no setting at all, and a global toggle re-opens the question of what happens when the preferred source lacks the selected language - which is exactly the defect fix (2) exists to remove. He also notes a missing language can be hand-added to achievements.json (https://ant-sh.blogspot.com/2026/09/translate-steam-achievements.html), which is worth reading before designing the wizard feature. TESTS THAT PIN THE CURRENT BEHAVIOUR, in tests/AchievementMetadataTests.cs, all named ResolvePreferringSchema_*: fix (1) inverts _ZeroPaddedSchemaName_KeepsInlineTextOverSchemaText (the direct assertion of today's rule) and _NumericSchemaUnderCollidingAppId_KeepsInlineText (the collision-guard rationale, which is the argument AGAINST fix 1 - read it before deciding). Fix (2) leaves _ExactMatch_StillLeadsOverInlineText and _MultiLanguageInlineText_HonoursLanguage green, because both request a language the schema actually has; the shipped defect has NO test at all, so fix (2) needs a new one - exact match, english-only schema, inline {english,russian}, language russian, expect russian. DOCS THAT STATE THE RULE AND WOULD HAVE TO CHANGE WITH IT, four places: CLAUDE.md ('Self-describing unlock files', the paragraph beginning 'One exception lives in FindDefinition'), docs/pages/usage/other-emulators.md, docs/pages/troubleshooting.md, and docs/pages/development/gbe-reference.md. The other-emulators one is a PUBLISHED PROMISE to users, not an internal note - it says a padding match 'adds the icon and fills anything the unlock file left blank, but leaves the text the unlock file already carries alone' - so fix (1) is a documented behaviour change, not a silent internal one.
