- [x] 2026-09-03 02:32 — Decide the two resolver fixes for issue #7 - they were both recommended this session and neither was accepted or rejected. (1) LET PADDING MATCHES LEAD LIKE EXACT ONES: matchedExactly has exactly one production use, the '(leading, filling) = matchedExactly ? ...' ternary at the end of ResolvePreferringSchema, and dropping the distinction is the whole change. ANCHORS ARE SYMBOL NAMES ON PURPOSE: this memo first carried five src/AchievementMetadata.cs line numbers and all five were stale within a day, off by ~50 lines, from edits made in the very session that wrote them. The argument for it: we already tell users to strip the zeros by hand, which converts a collision-CHECKED padding match (FindDefinition accumulates candidates and refuses an ambiguous one) into an UNCHECKED exact one (the exact pass returns on its first hit); the icon already crosses the line text is forbidden to cross (the IconPath assignment tests 'definition != null', not matchedExactly); and exact digits-only matching has no collision guard at all, though real Steam games ship achievements named 1..29. (2) PER-FIELD LANGUAGE PREFERENCE, which is a separate shipped defect found while tracing #7 and nobody has reported: on an EXACT match the schema leads unconditionally, and GetDisplayText returns a plain string verbatim, ignoring the language argument - so a user whose emulator inlines {english, russian} in the unlock file, against an english-only schema, with Achievement text set to russian, gets english. Proposed single rule covering both: per field, prefer whichever source actually carries the selected language; if neither does, prefer the schema. That fixes #7, fixes the inline-object case, and lets matchedExactly be deleted rather than replaced with something subtler. - [ ] 2026-09-03 02:36 — Parse the schema's 'hidden' field, and ship it with a consumer. AchievementDefinition (src/AchievementMetadata.cs:95) parses only name/displayName/description/icon, so the app cannot tell a description Steam REDACTED (because the achievement is hidden) from one the generator simply left empty - and that is the difference between 'nothing is wrong' and 'regenerate this config'. Measured across all 11 steam_settings schemas on this machine: every one carries 'hidden', and the blank-description count is always either 0 or EXACTLY the hidden count, never in between (Nier 30/30, LiS-Reunion 29/29, Persona 5 Royal 10/10, Aphelion 15/0, Elden Ring 36/0, Frostpunk 2 23/0, RDR 20/0). The decisive pair is Atomfall, which has two steam_settings folders with the same 25 hidden achievements: the coldclient copy has 25 blank descriptions, the root copy has 0 - same game, same hidden set, one generator filled them in and the other did not (see the separate memo about MetadataPath picking the wrong one of those two). Two implementation notes: (a) the TYPE is inconsistent across real files - string in 8 schemas, int in 3 - so it needs FlexibleBooleanConverter-style tolerance, not a bare int, exactly like FlexibleBooleanConverter/FlexibleInt64Converter already do for the unlock file; (b) do NOT add the property alone - a field no step reads violates the project's own rule. Ship it with its consumer: the GameCache 'Schema:' digest line and the diagnostic report's per-part description saying '31 blank, 31 of them hidden' instead of an unexplained 31. It is also a prerequisite for the wizard multi-language memo, which needs it to explain why descriptions stay empty in every language.
